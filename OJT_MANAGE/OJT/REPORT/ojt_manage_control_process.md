## 1. 목적 및 현행 운영

본 문서는 주간 업무보고, 내부 이슈, 외부 회사 협업을 연결하여 업무 접수부터 의사결정·조치·종료까지 추적할 수 있는 관리 절차를 제시한다. 보고된 문제가 담당자 지정과 실제 해결로 이어지고, 관련 기록을 일관되게 확인할 수 있도록 하는 것이 목적이다.

현재 확인된 부서 운영 방식은 다음과 같다.

| 관리 영역 | 현재 운영 방식 |
| --- | --- |
| 주간 업무보고 | 그룹 단위 1회, 부문 단위 1회, 전체 단위 1회 보고 |
| 내부 이슈 기록 | 기록의 원활성을 위해 기존 메일 중심 방식에서 Redmine으로 전환 |
| 외부 회사 협업 | Jira를 이용하여 외부 회사와 협력 |

이후에 제시하는 역할, 보고 연결 순서, 처리 상태와 관리 지표는 추가 운영 제안이다. 실제 보고 요일, 승인 권한, 처리 기한과 시스템 설정은 내부 검토 후 확정한다. 위 부서 운영 방식이 회사 전체에 적용된 것으로 전제하지 않는다.

## 2. 통합 관리 대상 및 책임

### 2.1 관리 대상

업무별로 담당자·기한·완료 기준을 정하고, 아래 항목을 기존 보고 자료와 시스템에 연결하여 관리한다.

| 관리 대상 | 핵심 관리 내용 | 관리 위치 |
| --- | --- | --- |
| 업무계획·일정 | 목표, 우선순위, 최초 계획일, 예상·실제 완료일 | 업무계획 및 주간 보고 |
| 내부 이슈 | 현상, 영향, 원인, 조치, 검증 결과 | Redmine |
| 외부 협업 | 요청 범위, 상호 담당자, 합의 일정, 결과물·수용 기준 | Jira |
| 위험·의존 관계 | 예상 문제, 선행 작업, 예방책, 대응 담당자 | 위험 목록 및 관련 업무 |
| 변경·의사결정 | 변경 영향, 결정 근거, 결정자, 후속 조치 | 관련 이슈 및 회의 기록 |
| 자원·비용 | 업무 집중, 인력 부족, 추가 지원·비용 필요 | 보고 자료 및 해당 승인 절차 |
| 산출물·지식 | 결과물 위치·버전, 검토 결과, 반복 문제의 해결 방법 | 기존 문서 저장소 및 관련 링크 |

문서와 일정은 회사의 기존 관리 수단을 우선 활용한다. 인사·회계·계약 등 전문 검토가 필요한 사항은 해당 절차와 연결한다.

### 2.2 역할 및 책임

| 역할 | 주요 책임 |
| --- | --- |
| 업무 담당자 | 업무 수행, 이슈 등록, 현황 갱신, 결과물 제출 |
| 그룹 책임자 | 그룹 내 검토·우선순위 조정, 부문 보고 정리 |
| 부문 책임자 | 그룹 간 일정·자원 조정, 전체 보고 요청 정리 |
| 전체 보고 의사결정자 | 권한 범위 내 부문 간 조정, 주요 우선순위·지원 결정 |
| 외부 협업 담당자 | Jira 요청 관리, 외부 담당자와 일정·결과 협의 |
| 결과 확인자 | 완료 기준에 따른 검증, 수용 또는 보완 판단 |
| 운영 관리 담당자 | 보고 취합, 기록 누락·지연 점검, 후속 조치 추적 |

역할은 기존 조직에 배정하며 겸임할 수 있다. 업무마다 책임 담당자 1명을 명시하고, 필요한 협조자와 결정권자를 연결한다. 계약·비용 등의 승인은 회사의 기존 권한 규정을 따른다.

## 3. 통합 운영 프로세스

업무 접수 → 분류·계획 → 수행·기록 → 보고·의사결정 → 조치 반영 → 검증·종료

| 단계 | 주요 활동 | 확인 사항 |
| --- | --- | --- |
| 접수·분류 | 일반 업무, 내부 이슈, 외부 협업, 위험·변경 구분 | 목적, 관리 위치, 관련 업무 |
| 계획 | 책임 담당자, 우선순위, 기한, 완료 기준 지정 | 수행 방향과 책임의 합의 |
| 수행·기록 | 작업 진행, 협업, 상태·예상 완료일 갱신 | 진척, 장애 요인, 증빙 |
| 보고·결정 | 주간 또는 수시 보고로 조정·지원 요청 | 결정 내용·근거 또는 재검토 담당·기한 |
| 조치 반영 | 결정 내용을 계획과 관련 시스템에 반영 | 담당자의 조치 수락과 실행 일정 |
| 검증·종료 | 결과를 완료 기준과 비교하고 종료 근거 기록 | 수용 여부, 남은 업무, 개선사항 |

같은 내용을 모든 시스템에 반복 작성하지 않고, 보고에는 요약과 관리번호·링크를 남긴다. 처리자의 완료 보고만으로 종료하지 않으며, 결과 확인자가 기준 충족 여부를 확인한다. 남은 조치는 담당자와 기한을 정하여 별도로 추적한다.

## 4. 주간 업무보고

### 4.1 보고 체계

현재의 단위별 주 1회 보고를 유지하면서 그룹 → 부문 → 전체로 검토 결과를 연결하는 방안을 제안한다. 실제 회의 일정에 맞춰 자료 마감과 결정 전달 시점을 조정한다.

| 보고 단위 | 주요 검토 내용 | 보고 결과 |
| --- | --- | --- |
| 그룹 | 담당자별 실적·차주 계획, 지연·이슈, 협조 사항 | 그룹 내 조치 및 부문 검토 요청 |
| 부문 | 그룹별 핵심 현황, 공통 이슈, 일정·자원 충돌 | 그룹 간 조정 및 전체 결정 요청 |
| 전체 | 부문별 주요 성과, 회사 차원의 영향, 부문 간 지원 | 우선순위·지원 결정 및 책임 단위 지정 |

상위 보고는 주요 변화, 영향, 필요한 결정을 중심으로 요약하고 세부 근거는 관련 기록으로 연결한다. 다른 그룹이나 부문에 영향을 주거나 담당 권한으로 해결하기 어려운 항목을 상위 보고 대상으로 삼는다.

### 4.2 준비 및 후속 처리

담당자는 보고 전 시스템의 상태와 예상 완료일을 갱신하고, 책임자는 계획 대비 차이와 결정 요청을 검토한다. 보고 후에는 결정 사항에 담당자·기한·관리번호를 부여하여 실제 업무에 반영하고 다음 보고에서 이행 결과를 확인한다.

자료에는 보고 기간과 현황 기준 시각을 표시한다. 보고 이후의 변화는 시스템에 최신 상태로 반영하되, 지난 보고는 당시 판단의 근거로 보존한다.

### 4.3 공통 보고 양식

보고 기본정보: 보고 기간 / 보고 단위·조직 / 작성자 / 현황 기준 시각

| 항목 | 작성 내용 |
| --- | --- |
| 금주 실적 | 완료 결과, 계획 대비 차이, 산출물 링크 |
| 진행 업무·차주 계획 | 담당자, 현재 단계, 최초 계획일·예상 완료일, 예정 작업 |
| 이슈·위험 | 영향, 대응 현황, Redmine 번호, 다음 조치 |
| 외부 협업 | Jira 키, 합의 기한, 외부 응답·결과물 상태 |
| 결정·지원 요청 | 결정할 사항, 선택안, 담당자 의견, 결정 필요 시점 |
| 이전 조치 결과 | 지난 결정의 이행 여부, 미완료 사유, 후속 기한 |

## 5. Redmine 기반 내부 이슈 관리

내부 이슈는 Redmine에서 현상부터 조치·검증까지 확인할 수 있도록 기록한다. 메일과 회의는 알림·논의에 활용하되, 업무에 영향을 주는 결정은 담당자가 관련 이슈에 정리한다. 과거 메일은 진행 중인 이슈와 중요 이력부터 필요한 근거를 연결한다.

### 5.1 등록 및 처리

| 항목 | 필수 기록 |
| --- | --- |
| 기본정보·현상 | 제목, 발생일, 등록자, 관련 업무, 재현 조건·증빙 |
| 영향·책임 | 일정·품질·비용 영향, 우선순위, 담당자·협조자 |
| 일정·대응 | 목표 기한, 다음 확인일, 임시 조치·해결 계획 |
| 연계 정보 | 관련 주간 보고, Jira 항목, 변경 결정 링크 |
| 결과 | 조치 내용, 결과 확인자, 검증 결과, 종료 근거 |

상태 흐름은 신규 → 검토·담당 지정 → 진행 중 → 검증 대기 → 종료를 제안한다. 실제 상태명은 현재 Redmine 설정과 맞춰 적용한다. 검증 실패 시 진행 중으로 되돌리고 보완 사유를 기록한다. 보류·외부 응답 대기에는 사유와 다음 확인일을, 중복·취소 종료에는 관련 항목이나 근거를 남긴다.

### 5.2 우선순위 및 수시 보고

업무 중단 등 긴급한 영향은 정기 보고를 기다리지 않고 책임자에게 즉시 알린 뒤 초기 조치와 기록을 보완한다. 주요 일정이나 외부 약속에 차질이 예상되면 영향과 대응안을 수시 보고한다. 일반 이슈는 목표 기한을 정해 주간 보고에서 추적하고, 개선 요청은 효과와 소요 자원을 검토해 우선순위를 정한다.

구체적인 응답·처리 시간은 업무 특성과 계약 조건에 따라 별도로 합의한다.

## 6. Jira 기반 외부 협업 및 내부 연계

### 6.1 외부 협업 절차

요청 정리 → Jira 등록 → 상호 담당자·일정 합의 → 수행·진척 확인 → 결과물 검증 → 수용·종료

Jira에는 요청 목적과 범위, 상호 담당자, 결과물, 수용 기준을 명시한다. 요청자의 희망 기한과 외부 회사가 수락한 합의 기한을 구분하고, 지연 또는 변경 시 사유·영향·새 일정의 합의 여부를 기록한다.

외부 결과물 제출 후에는 내부 확인자가 검증하여 수용 또는 보완을 판단한다. 결과물 위치·버전과 검토 결과를 남기며, 외부 공유 정보는 협업에 필요한 범위로 제한한다. 비용·계약 변경은 기존 승인 절차를 따른다.

### 6.2 Redmine과 Jira의 연결

내부 책임과 조치는 Redmine, 외부 회사와 합의한 요청·결과는 Jira에서 관리하는 방안을 제안한다. 내부 대응과 외부 조치가 함께 필요한 항목에 한해 연결하고, 모든 업무를 양쪽에 중복 등록하지 않는다.

Redmine에는 관련 Jira 키와 링크를 남기고, Jira에는 외부 공유가 허용된 참조정보를 기록한다. 외부 조치가 완료되어도 내부 적용·검증이 남으면 Redmine 항목을 자동 종료하지 않는다. 자동 연동 여부는 확인되지 않았으므로 주요 상태 변경과 보고 준비 시 담당자가 연결 상태를 점검한다.

예를 들어 외부 결과물의 오류는 Redmine에 내부 영향을, Jira에 수정 요청과 수용 기준을 기록한다. 외부 수정 후 내부 검증을 완료하고 각 시스템에 결과를 반영한 다음 주간 보고에서 조치 결과를 공유한다. 이는 절차 설명을 위한 예시다.

## 7. 변경·위험 및 산출물 관리

**변경 관리:** 범위·일정·비용·품질 또는 외부 합의가 바뀌면 요청 이유와 영향을 검토한다. 권한자의 승인·보류·반려 결과를 기록하고 승인된 변경을 계획과 시스템에 반영한다. 최초 계획과 변경 계획을 구분하여 차이와 결정 근거를 남긴다.

**위험·의존 관계:** 아직 발생하지 않은 예상 문제는 위험, 이미 발생한 문제는 이슈로 관리한다. 외부 회신 지연, 선행 업무 미완료, 담당자 업무 집중 등을 점검하고 예방책·담당자·다음 검토일을 정한다. 실제 발생 시 관련 이슈로 연결하고 후속 업무의 일정 영향을 조정한다.

**의사결정:** 기록은 안건 / 관련 관리번호 / 결정 내용·근거 / 결정자 / 조치 담당자·기한 / 검증 결과로 구성한다. 보류 시에도 추가 확인 담당자와 재검토 시점을 지정하고, 다음 보고에서 이행 여부를 확인한다.

**산출물·지식:** 기존 저장소에서 결과물의 위치와 버전을 관리하고 검증 대상·최종 수용 버전을 명확히 한다. 종료 시 남은 제약과 후속 업무를 확인하며 반복 이슈의 원인·해결 방법을 공통 문서에 축적한다. 접근 권한과 보존 기간은 회사 기준을 따른다.

## 8. 운영 점검 및 적용 방안

### 8.1 관리 지표

주간 보고에서는 지연·미결 이슈, 외부 협업 대기, 결정 사항의 이행을 점검한다. 월 1회 반복 문제와 절차를 검토하는 방안도 제안하며, 도입 여부와 담당자는 별도 결정한다.

| 지표 | 산정·점검 기준 |
| --- | --- |
| 기한 내 완료율 | 최초 확정 기한이 해당 기간에 속한 업무 중 기한 내 검증 완료 비율 |
| 미종료 지연 건수 | 최초 확정 기한이 지났으나 기준 시점까지 종료되지 않은 건수 |
| 이슈 처리 기간 | 기간 내 종료 이슈의 등록일부터 검증 종료일까지 소요 기간 |
| 외부 협업 대기 | 외부 회신·결과물 대기 건수와 대기 기간 |
| 후속 조치 이행률 | 기간 내 기한 도래 조치 중 기한 내 완료 확인된 비율 |
| 재작업·기록 누락 | 검증 실패·재발 건수 및 담당자·기한·완료 기준 누락 건수 |

분모가 0이면 해당 없음으로 표시한다. 승인된 일정 변경은 최초·변경 기한 기준을 구분하고 취소 업무는 별도 표시한다. 종료 이슈의 처리 기간과 함께 미종료 이슈의 경과 기간도 확인한다. 목표 수치는 실제 데이터를 수집한 후 정한다.

### 8.2 적용 순서와 기대 효과

현재 보고 양식과 시스템 설정 확인 → 공통 기록·보고 기준 합의 → 주요 진행 업무 정리 → 일부 업무 시범 적용 → 누락·중복 점검 → 적용 확대

시행 전 보고 요일·마감, 결정 권한, 긴급 연락 경로, 결과 확인자와 지표 집계 담당을 확정한다. 기존 시스템의 기능 변경이나 자동 연동은 운영 요구가 정리된 후 검토한다.

보고와 실제 조치 기록을 연결하면 업무의 책임·진척·완료 여부를 확인하기 쉬워지고, 조직 간 조정과 외부 협업의 추적성을 높일 수 있다. 실제 효과는 운영 후 지연·누락·재작업 및 후속 조치 이행 데이터를 통해 확인한다.
