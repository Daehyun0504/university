# 프로젝트 관리 실무 — 15주차 커리큘럼(안)

이번 학기에 진행되는 **「프로젝트 관리 실무」** 수업의 커리큘럼을 아래와 같이 구성했습니다. 검토 후 의견 부탁드립니다.

## 수업 개요

- **실습 프로젝트:** Python Socket을 활용한 미니 HTTP 웹 서버 개발
- **수업 기간:** 총 15주
- **진행 흐름:** 프로젝트 계획 수립 → 프로젝트 수행 → 프로젝트 통제 → 통합 변경 관리 및 종료

## 전체 일정 한눈에 보기

| 4~7주차 | 프로젝트 수행 | TCP 서버 구현, HTTP 요청·응답 처리, 네트워크 접속 확장 |
| 8~11주차 | 프로젝트 통제 | 진척도 점검, 기능·품질 통제, 네트워크 검증, 성과 분석 |
| 12~15주차 | 통합 변경 관리 | 변경요청 및 영향 분석, 변경 승인·반영, 통합시험, 종료 및 발표 |

## 1단계. 프로젝트 계획 수립 · 1~3주차

### 1주차 | 프로젝트 이해 및 목표 정의

- 프로젝트 관리의 개념 및 필요성 이해
- 미니 웹 서버 프로젝트 소개
- 최종 결과물 및 프로젝트 목표 정의
- HTTP 웹 서버 동작 구조 파악

**산출물:** 프로젝트 개요서

### 2주차 | 요구사항 및 범위 정의

- 서버 기능 요구사항 정의 및 필수·선택 기능 구분
- HTTP, TCP/IP, Socket 등 필요한 기술 요소 조사
- 프로젝트 범위 및 완료 기준 설정

**산출물:** 요구사항 정의서

### 3주차 | 일정 및 수행 계획 수립

- 개발 기능 단위로 작업 분해 및 WBS(작업 분류 체계) 작성
- 주차별 일정 및 마일스톤 설정
- 예상 위험 요소 파악 및 테스트 계획 수립

**산출물:** WBS, 프로젝트 일정표

## 2단계. 프로젝트 수행 · 4~7주차

### 4주차 | TCP 서버 기본 구현

- Python Socket 구조 학습
- `socket()` → `bind()` → `listen()` → `accept()` 흐름 이해
- TCP Echo Server 구현

**산출물:** TCP 서버 기본 코드

### 5주차 | HTTP 요청 분석 및 처리

- 브라우저 접속 실습 및 `GET / HTTP/1.1` 요청 확인
- 요청 라인(Request Line) 및 헤더(Header) 구조 분석
- 문자열 파싱(Parsing) 구현

**산출물:** HTTP 요청 파서(HTTP Request Parser)

### 6주차 | HTTP 응답 및 콘텐츠 제공

- HTTP 상태 라인(Status Line), 헤더(Header), 본문(Body) 구성
- HTML 파일 응답 구현
- UTF-8 인코딩 및 MIME 타입 처리
- `200` / `404` 응답 구현

**산출물:** HTTP 웹 서버 1차 버전

### 7주차 | 연결(Connection) 및 네트워크 확장

- HTTP/1.0과 HTTP/1.1 비교
- `Connection: close` 및 Keep-Alive 개념 이해
- localhost와 LAN 접속 비교
- 스마트폰 접속 시험

**산출물:** 웹 서버 2차 버전, 수행 결과

## 3단계. 프로젝트 통제 · 8~11주차

### 8주차 | 프로젝트 진척도 점검

- 계획 대비 실제 개발 진행률 확인
- WBS와 실제 수행 결과 비교
- 일정 지연 및 미완료 기능 파악

**산출물:** 진척도 점검표

### 9주차 | 기능 및 품질 통제

- 정상·비정상 HTTP 요청 시험
- 존재하지 않는 URL, 잘못된 메서드(Method) 등 예외 상황 확인
- 테스트 케이스 작성 및 결함 관리

**산출물:** 테스트 결과서, 결함 목록

### 10주차 | 네트워크 동작 검증

- localhost 및 LAN 환경별 접속 시험
- IP, 포트(Port), TCP 연결 상태 분석
- 필요 시 Wireshark를 활용한 TCP/HTTP 패킷 흐름 확인

**산출물:** 네트워크 검증 결과

### 11주차 | 성과 분석 및 개선사항 도출

- 계획 대비 일정·기능·품질 성과 분석
- 발견된 문제의 원인 분석
- 개선사항 및 변경 필요 항목 선정

**산출물:** 프로젝트 중간 평가서

## 4단계. 통합 변경 관리 · 12~15주차

### 12주차 | 변경요청 식별 및 영향 분석

- 새로운 요구사항 제시
- 변경요청서 작성
- 변경 시 일정·범위·품질에 미치는 영향 분석

**산출물:** 변경요청서, 영향 분석서

### 13주차 | 변경 승인 및 계획 반영

- 변경사항 우선순위 결정 및 적용 여부 판단
- 기존 WBS, 일정, 요구사항 수정
- 변경된 프로젝트 기준선 관리

**산출물:** 변경 관리 대장, 수정 계획서

### 14주차 | 변경사항 구현 및 통합시험

- 승인된 기능 추가 및 코드 수정
- 기존 기능에 대한 회귀 테스트(Regression Test) 수행
- 변경 전·후 결과 비교 및 통합시험 수행

**산출물:** 최종 웹 서버, 통합시험 결과서

### 15주차 | 프로젝트 종료 및 결과 발표

- 최종 결과물 시연
- 최초 계획과 최종 결과 비교
- 변경이 프로젝트에 미친 영향 분석
- 교훈 및 시사점(Lessons Learned) 작성 및 프로젝트 종료

**산출물:** 최종보고서, 발표자료
