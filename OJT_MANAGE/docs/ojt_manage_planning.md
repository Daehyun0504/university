# OJT 프로젝트 계획 및 수행 기록

기준: [15주 수업 계획](../ojt_manage_plan.md) · [진행 흐름](../ojt_manage_flow_diagram.md) · [구조도](../ojt_manage_dir_diagram.md)

## 1. 프로젝트 개요

목표는 Python Socket으로 미니 HTTP 서버를 구현하고 요구사항·작업·시험·변경을 연결하여 프로젝트 관리 과정을 실습하는 것이다. 사용자 시연은 로컬 또는 LAN 브라우저의 한글 페이지, 정적 CSS·이미지, 없는 URL의 `404` 응답으로 구성한다.

현재 상태는 **초기 구현 및 로컬 자동 검증**이다. 이후 주차의 실제 일정 평가, 팀 승인, LAN·스마트폰 검증, 최종 발표는 수행 시점에 이 문서를 갱신한다. 수행하지 않은 수업 활동이나 승인 이력은 완료로 기록하지 않는다.

실행 코드는 `src/mini_http/` 아래에 있다. 테스트 함수의 세부 경로는 `python3 -m pytest --collect-only -q`로 확인한다.

필수 구현 범위는 정적 GET, IPv4, 순차 처리, `Connection: close`다. Keep-Alive·동시 처리·TLS·동적 콘텐츠·요청 본문은 선택 변경 후보다. 이 구현은 전체 HTTP 표준을 지원하는 범용 서버가 아니다.

### 오류 응답 정책

| 상태 | 조건 |
| --- | --- |
| `400` | 잘못된 요청 라인·헤더·URL, HTTP/1.1 Host 누락, 중복 헤더, 요청 본문 길이 양수, 본문 길이 정보 충돌 |
| `403` | 문서 루트 밖 접근, 허용되지 않는 경로·파일 접근, 파일 크기 제한 초과 |
| `404` | 파일 없음 또는 디렉터리 조회 |
| `405` | GET 이외의 알려진 메서드. `Allow: GET` 제공 |
| `408` | 요청 헤더 수신 제한 시간 초과 |
| `417` | 지원하지 않는 Expect 헤더 |
| `431` | 요청 헤더 크기 제한 초과 |
| `500` | 예상하지 못한 파일 I/O 오류 |
| `501` | 모르는 메서드 또는 Transfer-Encoding |
| `505` | HTTP/1.0·1.1 외의 HTTP 버전 |

HTTP/1.0은 Host가 없어도 허용한다. 요청 본문은 읽지 않으며 `Content-Length: 0`만 허용한다. HEAD를 지원하는 것은 아니지만 HEAD 오류 응답은 본문 없이 전송한다. HTTP 버전·메서드가 겹치는 비정상 입력은 파서 검증 순서에 따라 먼저 감지한 오류를 반환한다.

## 3. 기술 조사 및 구현 결정

- `socket → bind → listen → accept`를 직접 호출한다. 송신에는 `sendall`을 사용한다. [Python socket 문서](https://docs.python.org/3/library/socket.html)
- 헤더 종료 `CRLF CRLF`까지 수신하고 요청 라인·헤더를 분리한다. 요청 시작부터의 전체 수신 시간을 제한한다. [HTTP/1.1 메시지 형식](https://www.rfc-editor.org/rfc/rfc9112.html)
- 수신·파싱·파일 처리·응답 생성 책임을 분리하여 내부 함수와 실제 연결을 각각 시험한다.
- 테스트 fixture는 서버를 임시 포트에서 시작하고 시험 뒤 종료한다. [pytest fixture 문서](https://docs.pytest.org/en/stable/how-to/fixtures.html)
- 기본 문서 루트는 소스 기준 `www/`다. 이 프로젝트는 저장소 직접 실행 또는 editable 설치를 기준으로 하며, 일반 wheel 설치 시에는 `--root`로 콘텐츠 위치를 지정한다.

## 6. 시험 계획 및 수행 결과

필수 기능의 자동 시험이 모두 통과하고 오류 입력 뒤에도 서버가 정상 요청을 처리해야 한다. 테스트는 단위·통합으로 나누고, 실제 LAN 및 브라우저 시각 검증은 별도로 기록한다.

```bash
source .venv/bin/activate
PYTHONPATH=src python3 -m pytest tests/ -v
```

| 시험 항목 | 방식 | 현재 결과 |
| --- | --- | --- |
| 요청 파싱·응답 길이·MIME·경로 보호 | 단위 시험 | 통과 |
| 소켓 접속·분할 수신·오류·수신 제한·연결 종료 | 임시 포트 통합 시험 | 통과 |
| 실행 명령·문서 루트·설정 오류·Ctrl+C | subprocess 통합 시험 | 통과 |
| 전체 자동 시험 | Python 3.12.3 / pytest 9.1.1 | **77개 통과 / 실패 0개**, 4.17초 |
| curl 정상·오류·정적 파일 | 실행 프로세스에 실제 HTTP 접속 | `/`·CSS·SVG `200`, 없는 경로 `404`, 루트 탈출 `403`; MIME·본문 바이트 길이 확인 |
| TCP Echo 송수신 | 실행 프로세스에 소켓 접속 | UTF-8·바이너리 10,262바이트 일치, SIGINT 정상 종료 |
| 패키지 설치·개발 환경 | editable 설치 및 `pip check` | 설치 성공, 의존성 충돌 없음 |
| LAN 다른 기기·스마트폰 | 동일 LAN에서 실제 기기로 접속 | 미실행 |
| 브라우저 시각 표시·Wireshark | 수동 확인 | 미실행, 패킷 관찰은 선택 |

curl 및 Echo 시험은 운영체제가 할당한 로컬 임시 포트에서 수행했고 종료 후 프로세스를 정리했다. 서버를 상시 실행해 둔 상태는 아니다. 압축 확장자 파일은 HTML로 잘못 표시하지 않고 다운로드 유형으로 제공하도록 보완했으며 해당 MIME 회귀시험을 포함했다. 실행 문서의 로컬 링크와 Bash 코드 블록 문법도 확인했다.

## 7. 진척도·결함·중간 평가

로컬 기본 서버와 자동 검증 코드를 준비했다. 실제 주차별 작업 시간과 일정 준수 자료는 아직 없으므로 일정 성과나 15주 전체 진척률을 산정하지 않는다. 시험 결과는 통과·실패·미실행을 구분한다.

| 결함 ID | 재현 절차 | 기대 / 실제 | 우선순위 | 담당·기한 | 상태·재시험 |
| --- | --- | --- | --- | --- | --- |
| 등록 시 BUG-001부터 부여 | 입력·환경·실행 버전 기록 | 결과 기록 | 지정 | 지정 | 수정 및 재시험 결과 기록 |

현재 자동 시험에서 확인된 미해결 결함은 없다. 환경 준비 중 시스템 `ensurepip`가 없어 기본 venv 생성이 실패했고, 생성된 `.venv`에 시스템 pip의 `--python` 옵션으로 pip·pytest를 설치하여 검증 환경을 준비했다. LAN·브라우저 검증은 아직 수행하지 않은 항목이다.

11주차에는 계획 대비 작업 완료, 미실행 시험, 미해결 결함과 원인을 검토한다. 현재의 개선 후보는 순차 처리 중 대기 연결 지연과 Keep-Alive 지원 여부이며, 수업 목표와 일정 영향을 분석한 뒤 변경 여부를 결정한다.

## 8. 변경요청·영향 분석·결정 이력

| 항목 | 현재 내용 |

승인된 기능만 구현하고 기존 시험을 다시 실행한다. 결함 수정은 재현 시험을 추가하고 재검증하며 범위·승인 일정 변경이 필요하면 변경요청으로 연결한다.

## 9. 최종 시연·보고·교훈 초안

시연 순서는 서버 시작 → 클라이언트 `GET /` → CSS·이미지 확인 → 없는 URL의 `404` → 자동 테스트 → 서버 종료다. [서버 명령](./ojt_manage_server_command.md)과 [클라이언트 명령](./ojt_manage_client_command.md)을 사용한다.

발표는 목표·범위, 모듈 구조, TCP/HTTP 처리 과정, 정상·오류 시연, 시험 증거, 최초 계획 대비 변경, 미검증 항목과 교훈 순서로 구성한다. 실제 결과 발표와 프로젝트 종료는 아직 수행하지 않았다.

초기 교훈은 네트워크 연결 검증과 내부 함수 검증을 구분할 때 실패 원인을 좁히기 쉽고, HTTP 본문 길이는 인코딩 후 계산해야 하며, 자동 시험 통과와 실제 기기 검증은 별도 증거가 필요하다는 점이다. 최종보고 시 실제 일정·변경 영향·잔여 결함·LAN 결과를 보완한다.
